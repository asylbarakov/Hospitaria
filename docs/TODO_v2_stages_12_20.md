1. Сначала прочитай `AGENTS.md`, `README.md`, `assets/manifest.md` и этот файл. Работай только над одним этапом за раз.

3. Файл не длиннее ~300 строк. Если растёт, разбей на модули. Логику без Phaser выноси в чистые модули (как `layoutBuilder.js`, `IsoGrid.js`), чтобы тестировать в node.
4. Баланс (цены, времена, награды) только в `src/data/*.js` константами. Никаких магических чисел в сценах.
5. Библиотеки: только Phaser 3.80.1 и EasyStar.js (разрешено с этапа 13, подключить через CDN в `index.html` с точной версией, например `easystarjs@0.4.4` с cdnjs или jsdelivr; в `AGENTS.md` дописать одну строку об этом). Больше ничего.
6. Тексты интерфейса на русском, идентификаторы на английском. Тон дружелюбный, без крови и жести, не медицинский совет.
7. Графика только из `assets/final` (PNG) плюс примитивы Phaser для подсветок. Новых картинок не рисовать; если не хватает ассета, зафиксировать в `docs/missing_assets.md` и использовать заглушку.
8. Изометрия: тайл 128x64, `x_screen=(x-y)*64`, `y_screen=(x+y)*32`, спрайты PNG в масштабе 2x (в игре scale 0.5). Не менять `IsoMath`, не придумывать свою проекцию. Порядок отрисовки только через `IsoDepth` (`sorter.add(obj, box, {dynamic:true})` для движущихся).

## Этап 13. Навигация (EasyStar)

Цель: надёжный поиск пути, плавное движение, обход людей и мебели, пересчёт при строительстве.

Шаги:
1. Подключить EasyStar через CDN в `index.html` (версия зафиксирована), дописать правило в `AGENTS.md`.
2. `src/iso/Pathfinder.js`: обёртка над `EasyStar.js` с `grid.toMatrix()`, диагонали без срезания углов (`enableDiagonals`, `disableCornerCutting`), `findPath(sx,sy,tx,ty) -> Promise|callback`, очередь с лимитом N запросов за кадр, вызов `calculate()` из `update`. В node EasyStar недоступен, поэтому интерфейс с резервной реализацией на `IsoGrid.findPath` (BFS) и общий контракт; тесты гоняют обе реализации через один набор кейсов.
3. Пересчёт: при `addItem`/`removeItem` обновлять матрицу (`setGrid`), у актёров с путём проверять, что следующий тайл ещё проходим; если нет, перепрокладывать маршрут.
4. Динамические препятствия: другие актёры не блокируют матрицу, но при столкновении на узком месте (дверь) один ждёт: простая резервация тайла двери (`world.reserveTile`), ожидание не дольше 1.5 с, потом обход или повтор.
5. Сглаживание: идти по центрам тайлов, углы закруглять не нужно; главное без дрожи. Скорость в тайлах/с в `src/data/actorConfig.js`.
6. Цели: функция `world.standTileFor(item)` возвращает ближайший проходимый тайл рядом с предметом (используется на этапах 14 и 15). Нужен контракт `facingTile` (куда смотреть при работе).
7. Тесты `tests/path_test.mjs`: из входа в каждую комнату и к каждому предмету (`standTileFor`), путь не пересекает слоты стен (`walk_test`-подход), после продажи стула путь перестраивается, закрытая дверь невозможна (дверной тайл всегда проходим), 200 запросов быстрее 50 мс в сумме.

Приёмка:
- Нажатие на недоступный тайл даёт красную вспышку, персонаж не двигается.
- Поставить диван в проходе: персонаж обходит, а если прохода нет совсем, игра предупреждает при постройке («Нельзя перекрывать единственный проход к комнате»). Реализовать проверку связности в `BuildMode.isValid()` через BFS от входа: после гипотетической постановки все двери и все предметы с подходом остаются достижимыми.
- Нет зависаний при 10 одновременных маршрутах.

Коммит: `stage 13: pathfinding`.
